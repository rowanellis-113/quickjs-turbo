Build and run
-------------
Use Linux x86_64,GCC/binutils,Python3,CMake and Ninja. The qualified toolchain is
GCC13.3/binutils2.42 on Ubuntu24.04. A fresh build needs no prior Windows object,
archive,executable,profiler or benchmark corpus. From this checkout:

  bash tools/build/product-linux.sh build/linux-native out/sdk-linux-native
  QJS_EXPERIMENT_ALLOCATOR=256 out/sdk-linux-native/bin/qjs -e 'print(1+2)'

The wrapper builds the complete product profile,runs CTest serially and installs
an SDK. The global-binding default is ON in QuickJSLinuxInterpreterOptions.
Use fresh build directories after compiler or native generator changes.
Strict LINUX_X86_64 requests require a supported real native backend;AUTO and
PORTABLE retain their documented safe fallback. The configuration policy now verifies existing GNU readelf/objdump executables
and their bounded version probes before adding native edges. Invalid tools use
PORTABLE under AUTO and fail at configuration under strict LINUX_X86_64.
Current source/SDK delivery bindings are recorded in LINUX-RELEASE.txt and the bundled release manifest.

The native VM has actual SysV public aggregates and an explicit measured private
register convention,not an entry thunk into the old interpreter. Source-owned
common algorithms are reused;ELF/CFI/platform ABI code stays in tools/elf,
src/x86/linux and asm/x86/linux. Frame128/state168,ownership,captured cells,
quotas,interrupts,GC roots,exceptions,reentry and process controls remain tested.
No PGO,padding,fixed base,address search or Windows compiler-profile substitution
is used. WSL hardware PMU availability does not determine backend correctness;
bounded software sampling has been validated and used on actual weak workloads.

Completion requires evidence for ALL of the following gates:

1. Build and packaging
   A documented Linux product command builds the real native backend with GCC,
   binutils, Python, CMake and Ninja. CMake reports LINUX_X86_64 only when that
   backend is actually linked. Strict requests fail on unsupported targets;
   AUTO/PORTABLE retain a tested safe fallback. Runtime/generated inputs have
   source-bound catalogues and receipts. Ordinary PIE/ASLR remains enabled.
   No Windows COFF object, compiler fingerprint or private offset is silently
   treated as a Linux ELF/SysV contract.

2. Actual native execution
   Public entry and return obey SysV, including the 16-byte JSValue aggregate.
   A measured private VM register convention supports JS-to-JS calls, returns,
   tail calls and C helpers without per-JS-call C recursion. Frame ownership,
   argument windows, captured cells, stack quotas, interrupts, GC publication,
   exceptions and reentry are tested. An entry thunk into the old interpreter
   or a C-only explicit frame prototype does not satisfy this gate.

3. Existing mechanism coverage
   Inventory the active Win64 call, property/cache, compiler, string/JSON,
   RegExp, array, closure and async-generator components. Every item has an
   explicit Linux route and execution evidence, or a documented, measured
   architectural/cost decision. Missing major mechanisms cannot be hidden by
   passing tests through fallback. Do not port dead/rejected experiments.
   Common logic stays common; platform ABI, ELF, CFI and relocation handling
   belongs in src/x86/linux, asm/x86/linux and tools/elf as appropriate.

4. Correctness and compatibility
   Native-specific regression/API/ABI tests, GC/OOM/interrupt/realm/callback
   behavior and independent installed consumers pass. Full Test262 uses the
   pinned corpus and failure identities; compare Linux native against stock
   and the Linux portable baseline, reporting inherited/fixed/new separately.
   Public API and serialization compatibility remain intact. Inspect ELF
   symbol bindings, relocation bounds, PIE/PIC, nonexecutable stack and CFI.
   Exercise native disable controls and unsupported compiler/platform fallback.

5. Performance and Linux opportunities
   Measure stock NG, product PORTABLE and native on the same Linux machine:
   micro57, the established JetStream17 subset and all eight V8-v7 cases.
   Use quick reversed paired screens first, confirm promising/concerning
   results with the original calibration, and retain memory/negative results.
   Price regressions against prior and stock per AGENTS.md; individual historical
   bests are not mandatory. No PGO, fixed image base, padding or address search.
   Profile actual weak workloads and consider Linux-specific opportunities,
   initially SysV aggregate returns/helper preservation and hidden/local ELF
   calls/PIE relocation cost. Record accepted, rejected or deferred decisions
   with evidence; do not add an unbounded micro-optimization campaign.

6. Reviewable delivery
   Produce coherent commits, a clean source tree, installable SDK and runnable
   public consumer, build/run documentation and a final mechanism/test/score
   report. Generated build products and captures stay outside tracked source.
   Verify the full checklist from current artifacts before declaring complete.

Measurement and delivery order
------------------------------
1. Freeze the current source,all three image hashes,toolchain and immutable
   workloads. Use stock NG0.15.1,product PORTABLE and Linux native on CPU2,
   serial reversed quick pairs with normal PIE/ASLR and original calibration.
2. Report micro ns/op,JetStream body milliseconds and original V8-v7 scores.
   Keep peak memory:micro actual GNU time child peak,JetStream VmHWM before
   supplemental checks,and V8 actual child GNU time peak including its complete
   original suite. Exclude launcher RSS and retain all negative samples.
3. Confirm only material promising/concerning cases,price costs against prior
   and stock per AGENTS.md,then profile actual loaded images and original work.
   Consider bounded SysV helper preservation/aggregate returns and ELF local/
   hidden-call or relocation costs;record accepted,rejected or deferred choices.
4. Qualify final current-source GCC modes,MinGW/MSVC/portable,full Test262,
   installed consumers,clean literal-LF archive and reviewable release commits.
   Audit all six gates before declaring the port complete.
