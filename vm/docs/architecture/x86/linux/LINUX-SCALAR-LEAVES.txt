Linux native scalar expression leaves
=====================================

This incremental optimization extends the accepted 7bb3293 Linux native child
entry. It does not change the pinned QuickJS-NG 0.15.1 sources or public ABI.
The original packaged 7bb3293 release remains an immutable historical delivery;
its exact executable hashes must not be assigned to this newer implementation.

Implementation and boundaries
-----------------------------
tools/elf/integer_expressions.py emits a bounded noncalling scalar worker into
the existing ELF entry assembly. It is reached only after the inherited normal
function/native-child, realm, host coherence, argument, frame/stack quota and
interrupt guards, and after the existing shared leaf alternatives have missed.

The grammar is 4..16 bytes: two integer arguments (indices0..3), current captured
cell values or integer constants; a binary arithmetic, bit/shift or comparison
operation; optionally an arithmetic-result comparison with a constant or logical
not; then return. Captured cells are read anew on each invocation; this does not
cache a value or require the cell to be immutable between calls.

Probes do not allocate, call JS/C, release values or write arguments, captured
cells or VM state. An admitted return decrements the existing interrupt counter
once. Objects, floats, BigInt, uninitialized cells, unsupported bytecode, integer
overflow and negative-zero arithmetic use the inherited call protocol with its
original arguments. No new JS frame, runtime field or private ABI offset exists.
The existing red-zone scratch and SysV RAX/RDX JSValue return convention apply.

src/x86/linux/integer-expression.c owns a private one-byte atomic mode and
cold environment lookup, outside the interpreter translation unit. A preserved
six-GPR/CFI-covered initialization entry runs after the inherited stack guard
and before private red-zone views are established. Both new ASM workers append
after existing constructors; platform source inclusion is LINUX_X86_64 only.

For a fresh-process ablation, set QJS_DISABLE_NATIVE_INT_EXPRESSION_LEAF to any
value, including0. It retains the original native child call. This is a process
control, not a live runtime/API setting. PORTABLE and Windows do not include
this worker; they continue to use their existing implementations.

Layout and performance limits
-----------------------------
The linked register VM and Linux entry initializer retain exactly their old
addresses and bytes; the main VM table positions also remain. LegacyCallInternal
retains its entry and size, but some relocation bytes differ. Some native entry
constructors move16 bytes. Do not claim full executable/data layout identity.
No PGO, padding, fixed image base or favorable-address selection is used.

Original calibrated lazy-collections repeats about10..13% less time; four
paired processes per image average96.84ms accepted and85.64ms new. Current stock
NG0.15.1 averages70.19ms, so this workload still has a22% gap to stock. A fresh
MinGW original-body comparison is about80.95ms; cross-OS means are descriptive,
not proof of an isolated compiler/ABI cost. Full native generator execution is
not implemented by this leaf and remains a larger separate feature decision.

Engine peak RSS is effectively unchanged in the full screen, with no frame or
runtime-state growth. Acceptance weighs these explicit costs against the real
