Linux string kernels and native append
=====================================

Scope and normal build
----------------------
tools/x86/linux/string_workers.py owns the accepted concat/local-rope, add_loc,
single-character cache/index and Latin-1 localeCompare C algorithms in the
actual generated Linux core TU. tools/x86/linux/string_vm.py connects the register
VM and the no-call byte-append lane. Normal CMake generation binds the typed
header, measured layout, VM assembly and STRING-WORKERS.json in PREPARE/BUILD.
The pinned upstream files and public API are unchanged.

  bash tools/x86/linux/build/product-linux.sh build/linux-native out/sdk-linux-native
  ctest --test-dir build/linux-native --output-on-failure -R 'string|locale|rope'

The original string-family checkpoint below is historical. Later native-entry
and LINUX-VM-LEAVES.txt checkpoints add slice/number builtin views and the
complete compound localeCompare/character-set leaf routes. Whole-image
performance and Linux release qualification remain separate gates.

Algorithms, ABI and ownership
-----------------------------
The common rope-aware equality repair is retained once in its existing core
owner. The complete shared concat/local-rope algorithms and add_loc C body
retain consumption, reference count, allocation failure, GC roots and exception
cleanup. Nonprimitive operands retain the original coercion boundary.

The native append block uses the shared instruction factory after validating
the actual Linux string/rope/runtime fields, bitfields and opcode constants.
Allocator identity is checked before reading the pool header. No allocation,
C call, callback or final release occurs after the commit guards. Independent
atomic Linux policy bytes replace the Windows runtime-padding controls. The
two add_loc cold edges and three short-add miss edges retain their original
fallback and VM unwind protocol. Direct-only cold blocks have explicit CFI;
actual indirect dispatch/C-method targets retain the measured CET checks.

The existing GNU small-character algorithm is compiled against real Linux
types. Its optional16 runtime slots each hold256 strong string-atom owners;
the pointer table is32768 bytes. Saturation retains the original constructor.
The interning guard prevents recursive atom-table growth. Every original
single-character constructor route uses this owner. The exact FreeRuntime
pre-GC boundary detaches all cached owners, then calls the original GC;
rt->in_free prevents cleanup reentry from repopulating the cache. A runtime
keeps QuickJS's normal single-executor requirement; independent runtimes can
use separate slots concurrently.

The complete GNU string-index kernel handles the two indexed-get forms with
the original typed C fallback. The common Latin-1 localeCompare kernel is an
explicit method-table target. The later VM-leaf integration also compiles the
complete compound C algorithm against actual Linux bytecode/PIC types and
routes it through the measured SysV uint64_t helper bridge.
No COFF objects, mirrored private context structs or Windows TLS are used.

The existing register/interpreter controls remain applicable. A native build
without the optional allocator passes with typed string fallbacks and without
the pool-dependent native append. AUTO without the required source overlay
selects PORTABLE; an explicit unsupported native request fails at configure.
