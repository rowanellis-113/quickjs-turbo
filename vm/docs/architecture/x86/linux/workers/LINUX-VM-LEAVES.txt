Linux in-VM primitive, compound and character leaves (development)
=================================================================

This group reuses the complete accepted tools/x86/common/codegen/leaf-entry.py kernels
inside the existing Linux register VM. It does not substitute a C entry or a
benchmark-specific implementation. The accepted Windows product is unchanged.
Constructor/root3, deferred publication and the remaining mechanism families
still precede whole-port correctness, performance and release acceptance.

Shared semantics and ownership
------------------------------
Seven primitive classes cover integer/undefined/null/boolean constants,
argument identity, argument-plus-integer and two-argument integer addition.
The unchanged exact-bytecode classifiers and live arity, type, overflow,
realm, arena, logical/physical quota and interrupt guards remain. Returned
references are duplicated before the original caller releases its arguments.
Misses restore the live callee and use the original metadata/frame path.

With property IC enabled, the exact compound wrapper reads two ordinary own
data properties and calls the live original String.prototype.localeCompare
builtin. Its source-owned C helper uses actual Linux bytecode/PIC types and
offsets, including PIC and hash-slot fallback. String/realm/prototype/builtin
identity and flat Latin-1 guards remain. Replaced builtins, getters, wide
strings, shapes and misses retain the original observable path.

The character-set kernel recognizes the original exact three-literal OR
pattern, with the same realm and one-byte input/constant guards. It retains
two interrupt polls on the first match and three on later/no-match paths.
Ordinary primitives retain one poll; the compound path retains two.

These are direct continuations in the single existing VM activation, with
the same CFA144 and original finalizer-safe result/argument consumer. No JS
frame, state, public JSValue or GC-root field is added; no arena cursor,
segment, committed charge or runtime frame is changed at the leaf commit.
Positive metadata uses the original three unused flag bits; the ready bit16
is deliberately clear. Serialized/compiler padding is not preclassified.
Dirty/clean dispatch-table selection remains a separate unported group.

Actual SysV integration
-----------------------
The compound helper has the measured signature
  uint64_t (JSContext *, JSFunctionBytecode *, const JSValue *, const JSValue *)
Its bridge moves private RCX/RDX/R8/R9 to SysV RDI/RSI/RDX/RCX, preserving full
pointer width and the VM's nonvolatile private registers. Cold null/null
probing and hot success retain distinct uint64_t result bits. The existing
272-byte hypothetical physical-quota address is a LEA, not a stack access.
Other private scratch accesses retain the generation-time bounds checks.
Both helper and live VM frames have matching unwind information.

Presence, including value0, disables QJS_DISABLE_FRAME_LEAF_ENTRY,
QJS_DISABLE_FRAME_COMPOUND_LEAF and QJS_DISABLE_FRAME_CHARACTER_SET_LEAF.
QJS_DISABLE_LOCALE_COMPARE_LATIN1 also disables the compound entry. Values are
cached in independent atomic bytes by cold bytecode admission. A build
without property IC emits only ordinary primitive leaves. Whole-configuration
requalification remains a final gate; this statement is not an IC-OFF test.
