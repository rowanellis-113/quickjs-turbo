Linux unified slow routing: qualified development increment
============================================================

MinGW performance parity remains OPEN. This increment repairs a demonstrated
Linux routing cost; build/correctness qualification and a local speed gain do
not close that whole-platform performance requirement. The original immutable
deliveries retain their source/image identities. Stock means NG0.17.0 7b5f588e0f,
not Bellard QuickJS2026. All19 pinned sources remain unchanged.

Mechanism and scope
-------------------
The previous Linux literal fallback walked every logical ancestor to choose
between the ordinary C executor and its complete checkpoint/forward/constructor
superset. Repeating this classification at depth costs O(depth) per slow step.
The accepted MinGW slow-direct policy already uses the complete executor.

JS_LinuxUnifiedSlowSelect is a51-byte SysV state-pointer-to-int tail dispatcher.
Literal and indexed gateways run before it. With existing slow-direct mode
ready/enabled and observation disabled, native for_of_next keeps its worker;
other cases, including pending exceptions, enter COMPLETE JS_FrameVarargsSlow.
It preserves the original semantic bodies, polls, quota, GC/publication and
frame/iterator/forward/constructor cleanup. It does not write VM state, allocate,
add a JS/C frame or add runtime/state/control bytes. No benchmark name or data
selects the route. It uses the measured168-byte private state and existing mode.

Cold255, disabled and observed modes retain the exact old selector. Existing
coherent SlowDirectConfigure initializes the shared policy on its normal first
eligible C step. QJS_DISABLE_FRAME_SLOW_DIRECT, by presence including0, disables
this route AND existing indexed/instanceof steps. QJS_OBSERVE_FRAME_SLOW_DIRECT
also retains the original selector here. Controls have fresh-process scope.
Compare OLD-OFF against NEW-OFF; this is not a pure single-feature ablation.

Emission requires the native indexed, literal and iterator contracts. Other
generator configurations retain their existing targets. Windows runtime input
is unchanged. Source ownership stays in tools/elf and src/x86/linux; no new
public API, serialized format, checked-in assembly family or C TU is added.
