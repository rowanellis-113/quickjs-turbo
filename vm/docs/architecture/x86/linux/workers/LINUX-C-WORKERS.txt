Linux source-owned C workers (development qualification)
======================================================

The port reuses the reviewed C algorithms before Win64 COFF extraction/routing.
The normal Linux generation edge compiles them with real core types and helpers
in the derived core translation unit. Public/private C boundaries are lowered
by GCC as SysV; no Win64 private-struct clone, object patch or compiler profile
is admitted for Linux. The pinned upstream files remain unchanged.

tools/x86/common/codegen/generator-capability.py:prepare_source and
tools/x86/common/codegen/prepared-callback.py:prepare_source contain the shared extraction
phases. Win64 retains its original reviewed caller/callee and routing gates.
Independent preparation comparisons produced the same C bytes as those original
phases. That comparison is narrower than a fresh Windows build/qualification.

Current modules
---------------
Async generators: direct await, fulfilled-Promise await and private output
capability elision are enabled with their existing presence-disable controls.
The original request owns its public Promise. Both undefined resolver slots
identify a private capability-free request. Original and new recovery, reject,
completed-return and late-hook paths share the patched settlement owner in
the same TU. Real fresh CData callbacks, reaction jobs, context ownership, FIFO,
interrupt polls, visible hooks, GC fields and request cleanup are retained.
Ordinary async output-capability elision is not enabled by this module.

Prepared callbacks: complete current-source every/some/forEach/map/filter and
reduce/reduceRight loops, including TypedArray variants, have14 explicit
method-table routes. Readonly and owned-formal activations share the common C
admission/lifetime implementation. The Linux selector uses actual frame, state,
segment and shared-anchor types, compiler TLS and the same register VM. It
checks runtime modes, current host identity/coherence, callee, kind, captures,
argc, capacity, stack budget and interrupt boundary on each prepared entry.
Root/locals/operand state resets per callback; borrowed values and owned-formal
cleanup remain distinct. Overflow, unsupported callees and disabled controls
retain the typed original entry. No per-call bytecode validation is introduced.

Added workers/controls use named ELF text/BSS families. This avoids introducing
their large copied loops into ordinary text, but is not a performance proof or
an address-preservation claim. Measurements wait for broader mechanism coverage.

Known upstream OOM failure
-------------------------
The fixture's optional `linux-prepared-callback map-oom` reproduces a0.17.0 array
species construction crash: add_property(length) can return NULL in
JS_NewObjectFromShape, followed by an unchecked pr->u.value store. The same
fault4 reproduces with the stock archive, pre-worker native archive and new
worker OFF. Raw reproducer/control results are retained outside the source
tree. This is a known inherited defect, not a passed fault case. The default
reduce sweep independently exercises the new capsule's growth/cleanup without
that unrelated species-constructor path; the optional map reproducer remains.
