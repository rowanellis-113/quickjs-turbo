macOS x86-64 native Mach-O ASM VM (MACOS_X86_64)
==============================================
Release: v0.17.0-turbo.5 (2026-11-28; pinned QuickJS-NG 0.17.0 / 7b5f588e0f)

Overview
--------
`MACOS_X86_64` provides the native Mach-O register-frame assembly VM for Intel
macOS (Darwin x86-64 LP64) with Apple Clang 15+ and Xcode Command Line Tools
(`otool`, `dwarfdump`). On Apple Silicon (`Darwin arm64`) and under sanitizers or
fuzzers, `QJS_FRAME_BACKEND=AUTO` automatically falls back to `PORTABLE`.

Build and mechanism
-------------------
  bash vm/tools/x86/macos/build/product-macos.sh build/macos-x86_64 out/sdk-macos-x86_64

- Source translation: `vm/tools/x86/macos/adapt_macho.py` translates the generated
  Linux x86-64 SysV/ELF runtime and assembly outputs to Mach-O ABI/section directives
  (`_symbol` prefixes, `__TEXT/__DATA` segments, RIP-relative addressing, DWARF EH frames),
  records per-file SHA-256 receipts for all adapted includes in `MACOS-ADAPT.json`,
  and restores `always_inline` with exact anchor-count assertions on small hot helpers
  (`js_linux_try_dense_next`, `js_linux_regexp_empty_guard`,
  `js_linux_regexp_split_guard`, `js_str_key_cache_probe`) that Apple Clang otherwise
  leaves out-of-line after `noipa -> noinline` translation.
- Apple Clang indirectbr codegen mitigation (`vm/cmake/x86/macos/Interpreter.cmake`,
  `vm/CMakeLists.txt`): when `quickjs-linux-foundation.c` defines both
  `JS_LegacyCallInternal` and `JS_CVMResumeInternal` in the same TU, Apple Clang 15's
  pre-RA early tail duplication expands the shared `indirectbr` block across ~300 opcode
  blocks, causing `RAGreedy` to emit stack-to-stack copies across every opcode boundary
  (`21,742` vs `1,352` [`16.1x`] stack-addressing instructions in `_JS_LegacyCallInternal`;
  `10,310` vs `1,501` [`6.87x`] in `_JS_CVMResumeInternal`, measured over exact linked
  function boundaries). Combined compiler-flag probing enables
  `-mllvm -tail-dup-indirect-size=4` and `-mllvm -tail-dup-placement-threshold=8` on
  `qjs_macos_core`, while `Release`/`MinSizeRel` builds enable `-fomit-frame-pointer` on
  `qjs-core`/`qjs` (preserving frame pointers in `Debug` and `RelWithDebInfo`).
- Verification (`v0.17.0-turbo.5`, Apple Clang 15.0.0.15000100, Darwin 22.6.0):
  - `adapt_macho.py` adapts `35` C/H files, `30` includes (SHA-256 verified), and `3`
    assembly files (placing `JS_CVMRunFastSegment` exclusively in `__TEXT,__qjs_cvm`
    and the read-only `JS_CVMFastEligible` table in `__TEXT,__const`).
  - `cvm_fast_native.py` emits full SysV DWARF CFI (`.cfi_offset` for `rbx, rbp, rsi, rdi,
    r12..r15` and epilogue `.cfi_restore`) so `_JS_CVMRunFastSegment` retains an exact
    DWARF FDE (`0x04xxxxxx` compact-unwind DWARF mode, `CFA=RSP+72`) spanning its full
    11,554-byte body rather than a truncated compact-unwind encoding.
  - `record-native.py` verifies Mach-O PIE, non-executable stack, `W^X` section hygiene,
    actual `__TEXT` RX permissions (`0x5`), symbol-to-section containment (`__qjs_cvm`,
    `__qjs_varg`, `__TEXT,__const` for `JS_CVMFastEligible`), exclusive `__TEXT,__qjs_cvm`
    full-span FDE coverage with exact 24-bit compact-unwind FDE offset matching, exact
    machine-code push/pop boundaries (start `+12`, or `+16` with an entry ENDBR64,
    first pop complete at `-11`) and step-by-step
    decoded rows (`CFA=RSP+72`, all 8 saved registers, `RIP=[CFA-8]`), separate
    `cvm_asm_linked` vs `cvm_fast_segments` flags in `BUILD.json`, and complete
    `adapted_include_files` SHA-256 receipt parity with `adapted_includes`.
  - Full native CTest (`-DQJS_FRAME_BUILD_TESTS=ON`): `962/962` passed (including
    `macos-x86-cvm-unwind` runtime Darwin `libunwind` recovery at the first, middle
    and last bytes of the body rule, using non-signal PCs `+13` (`+17` with ENDBR64),
    midpoint, and `-11` relative to the FDE end for the final probe. The probe range is
    checked against independent Mach-O `getsectiondata("__TEXT", "__qjs_cvm")` bounds); `test_macho_x86.py`
    (`MACHO_X86_POLICY_OK cputype=0x01000007`, including negative tests for truncated
    FDEs, `+18`/`-20` edge shifts, compact-unwind offset mismatches, missing adapt
    receipts, and stale incremental pregen files), `test_arch_boundaries.py`,
    `validate_layout.py --require-native`, `contracts.py` (`511` receipts, `0` stale),
    Python 3.9-compatible receipt-driven `export-pregen.py` + zero-Python
    `QJS_USE_PREGEN_ASM=ON` build (`133` files), and installed SDK C & C++11 consumer
    tests (`2/2`) all pass.
- macOS ARM64 (`macos-arm64-sdk.tar.gz`, `PORTABLE` backend) is cross-compiled on
  `macos-15-intel` CI with `lipo -archs` architecture verification and downstream
  CMake consumer link validation; native Apple Silicon runtime execution tests are
  not yet run in CI.
