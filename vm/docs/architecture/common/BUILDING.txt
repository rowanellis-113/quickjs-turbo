Building and running the product
================================
Current pinned base: QuickJS-NG 0.17.0 (`7b5f588e0f9b643e2996f291bfc861abeaceddc2`,
aligned with txiki.js v26.11.0 `BC_VERSION 29`). Updating upstream is a reviewed
port validated by `vm/cmake/QuickJSUpstreamPin.cmake`, not part of a normal build.
Preserve LF line endings (`core.autocrlf=false`) in Git checkouts; source pins and
native input receipts are SHA-256 verified.

Prerequisites
-------------
All native platforms: CMake 3.20+, Ninja, Python 3.10+, and a 64-bit C11 compiler:
- Linux x86-64 (`LINUX_X86_64`): GCC 13/14+ (`glibc` or `musl`), GNU binutils (`readelf`, `objdump`, `as`).
- Linux ARM64 (`LINUX_AARCH64`): native GCC 13/14+ or `aarch64-linux-gnu-gcc` + `qemu-aarch64` (`qemu-user`) for x86 cross testing.
- macOS x86-64 (`MACOS_X86_64`): Apple Clang 15+, Xcode Command Line Tools (`otool`, `dwarfdump`).
- Windows x86-64 (`WIN_X86_64`): MSVC 19+ (`cl` + `ml64`), LLVM `clang-cl`, or MinGW-w64 GCC 13+ (zero GNU binutils required for MSVC/`clang-cl`; keep MinGW `bin/` first on `PATH` when running MinGW binaries/CTests so 32-bit `libwinpthread-1.dll` elsewhere on `PATH` cannot shadow 64-bit runtime DLLs).

`QJS_FRAME_BACKEND=AUTO` (default) selects the native register-frame ASM VM on
supported targets and automatically falls back to `PORTABLE` C on macOS ARM64,
shared-library builds, or under sanitizers (`ASan`/`UBSan`/`TSan`/`MSan`/Fuzz) and
`FORCE_GC_AT_MALLOC`. Strict backend names fail at configure time if prerequisites
are missing.

Build commands by platform
--------------------------
Linux x86-64 (`LINUX_X86_64` full product wrapper + SDK + CTest):
  bash vm/tools/x86/linux/build/product-linux.sh build/linux out/sdk-linux
  QJS_EXPERIMENT_ALLOCATOR=512 ./out/sdk-linux/bin/qjs -e 'print(1 + 2)'

Minimal Linux x86-64 CMake build:
  cmake -S vm -B build/linux-min -G Ninja -DCMAKE_BUILD_TYPE=Release -DQJS_FRAME_BACKEND=AUTO
  cmake --build build/linux-min --parallel

Linux ARM64 (`LINUX_AARCH64` native or x86 cross + QEMU):
  bash vm/tools/arm64/build/product-linux-aarch64.sh build/arm64 out/sdk-arm64
  # Portable C fallback on ARM64:
  bash vm/tools/arm64/build/product-linux-aarch64-portable.sh build/arm64-c out/sdk-arm64-c

macOS x86-64 (`MACOS_X86_64`):
  bash vm/tools/x86/macos/build/product-macos.sh build/macos-x86_64 out/sdk-macos

Windows x86-64 (`WIN_X86_64` — unified CMake flow for MSVC, `clang-cl`, or MinGW):
  cmake -S vm -B build/win-x86_64 -G Ninja -DCMAKE_BUILD_TYPE=Release ^
    -DQJS_FRAME_BACKEND=AUTO -DQJS_PROPERTY_IC=ON -DQJS_FRAME_BUILD_TESTS=ON
  cmake --build build/win-x86_64 --parallel
  ctest --test-dir build/win-x86_64 --output-on-failure

MSVC defaults to `/MD`; pass `-DCMAKE_MSVC_RUNTIME_LIBRARY=MultiThreaded` for static
CRT `/MT` (`verify_pe_imports.py` checks `KERNEL32.dll`-only PE imports). Pass
`-DQJS_DEFAULT_EXPERIMENT_ALLOCATOR=256` (or `512` on Linux) when embedding into
hosts that do not set `QJS_EXPERIMENT_ALLOCATOR` in the process environment.

Portable C fallback (macOS ARM64 / sanitizers / generic targets):
  cmake -S vm -B build/portable -G Ninja -DCMAKE_BUILD_TYPE=Release -DQJS_FRAME_BACKEND=PORTABLE -DQJS_FRAME_BUILD_TESTS=ON
  cmake --build build/portable --parallel && ctest --test-dir build/portable --output-on-failure

Embedding (`quickjs-turbo::qjs` & `quickjs-turbo.h`)
----------------------------------------------------
Consume either an installed SDK via `find_package(quickjs-turbo CONFIG REQUIRED)`
or vendor `add_subdirectory(vendor/quickjs-turbo/vm)` directly:
  target_link_libraries(your_app PRIVATE quickjs-turbo::qjs)

- Under `add_subdirectory()`, `QJS_BUILD_CLI` and `QJS_ENABLE_INSTALL` default to `OFF`.
- Host LTO (`-flto`, `/GL`) stays enabled for the application; native ASM/bridge
  objects isolate `-fno-lto` / `/GL-` locally on `qjs` / `qjs-core`.
- Use `#include "quickjs-turbo.h"` (`QJS_TurboOptionsInit`, `QJS_SetTurboDefaults`,
  `JS_SetRuntimeTurboOptions`, `JS_PurgePropertyIC`, `QJS_GetTurboInfo`) to configure
  PIC-only (`own_bytecode_tail = QJS_TURBO_OFF`), IC warmup (`property_ic_warmup`),
  and idle slab reclamation without `getenv()`.

Offline Python-free builds (`QJS_USE_PREGEN_ASM`)
-------------------------------------------------
Export a SHA-256 verified assembly bundle once, then build with zero Python:
  python3 -B vm/tools/common/export-pregen.py --source vm --build <build-dir> --output <pregen-dir>
  cmake -S vm -B build/offline -G Ninja -DCMAKE_BUILD_TYPE=Release \
    -DQJS_FRAME_BACKEND=<LINUX_X86_64|LINUX_AARCH64|MACOS_X86_64|WIN_X86_64> \
    -DQJS_PROPERTY_IC=ON -DQJS_USE_PREGEN_ASM=ON -DQJS_PREGEN_DIR=<pregen-dir>

Full Test262 verification
-------------------------
