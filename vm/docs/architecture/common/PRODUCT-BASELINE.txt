Current embedder, density & cross-platform baseline, 2026-11-22 (v0.15.1-turbo.5)
=================================================================================
Pinned upstream remains QuickJS-NG 0.15.1 (bf8988fc401e737f9946cd10a3463b48aab0fd7e);
all 19 upstream source pins are unchanged. Release v0.15.1-turbo.5 resolves the
high-density memory vs native performance trade-off and promotes QuickJS-Turbo
to a first-class embeddable C/CMake library across Linux, macOS, and Windows:
1. Decoupled PIC-only (no-tail) mode (mode == 4): own_bytecode tail copies can
   be disabled via QJS_DISABLE_OWN_BYTECODE_TAIL=1 or explicit C API
   (own_bytecode_tail = QJS_TURBO_OFF) while keeping native assembly Property
   ICs (JS_FrameOwnBytecodeM1/M2/M3) fully active via reserved[3] (+5).
2. Low-bit tagged property_ic warmup + JS_PurgePropertyIC(rt): reuses odd low
   bits (3..4095, max warmup 2047) on JSFunctionBytecode.property_ic (+0 bytes
   struct growth, -1 hot branch on x86-64, +0 instructions on ARM64; default
   warmup=0 preserves upstream CLI behavior) plus runtime slab reclamation via
   rt->property_ic_list.
3. Explicit C configuration & diagnostic API (vm/quickjs-turbo.h):
   QJS_SetTurboDefaults, QJS_GetTurboDefaults, JS_SetRuntimeTurboOptions,
   JS_PurgePropertyIC, and structured read-only QJS_GetTurboInfo(rt, &info)
   replacing getenv() + constructor-priority workarounds.
4. First-class CMake embedding (quickjs-turbo::qjs): local LTO isolation
   (-fno-lto / /GL- on qjs/qjs-core only), automatic AUTO fallback to PORTABLE
   under ASan/UBSan/TSan/MSan/Fuzz, add_subdirectory() support with automatic
   top-level compile_commands.json/CMakeCache.txt resolution, and Linux ARM64
   AUTO selection with both glibc and musl support.
5. Source-level Windows x86-64 native ASM VM (WIN_X86_64): MSVC (cl + ml64) and
   clang-cl support without GNU binutils, full Win64 ABI (32-byte shadow space,
   callee-saved GPR/XMM invariants, SEH .pdata/.xdata unwind), native Property
   IC, and MSVC unsigned 3-bit JSGCObjectHeader.gc_obj_type bitfield fix in
   hybrid_gc.py.
6. Optional pre-generated assembly bundles: deterministic export via
   vm/tools/common/export-pregen.py and pure-CMake SHA256-verified offline
   builds via -DQJS_USE_PREGEN_ASM=ON -DQJS_PREGEN_DIR=<dir>.

Bounded optimization exit
--------------------------
The last investigation decided two candidate slots using quick original
RayTrace/EarleyBoyer/RegExp/Splay screens before expensive confirmation:
  pool512:about+0.69%Windows/+0.68%Linux diagnostic score;parked,not promoted;
  mimalloc:about-13.7%Windows/-2.4%Linux diagnostic score;not accepted.
The mimalloc control used the public allocator API and the exact acceptedSDK
archive. Its memory reduction did not establish a speed benefit;pool-specific
safe fastpaths are part of the intervention. No mimalloc dependency is added.

The entry/acceptance target was stable wholeV8>=+1%,or a target>=+5% with
nonnegative full application result,stock-priced costs,memory and correctness.
Neither candidate established this evidence. The small512 tendency is retained;
it is not described as a proven zero full-suite effect. No candidate full-suite
or newJet17 stable result is claimed. The performance round is closed after
those two decisions;ABI/GC/core-layout redesign requires a separate measured
application budget and bounded proposal. This is not an architecture ceiling.

Profiles and experiments remain outside the product repository. The release
contains compact decisions/results and qualification receipts,not process
captures or optional research code required by normal builds.
