=============================

0.15.1 public API. Ordinary upstream defaults differ. Sources are grouped by
function/platform under common/ | arm64/ | x86/, not by historical experiment or
benchmark name.

Remaining x86 -> ARM64 VM shell, entry, and cache micro-candidates were evaluated via
Graviton2 orthogonal ablation (A0-A3) and retired because ARM64 R89 already saturated
effective fast paths while extra shell/cache changes were neutral or layout-sensitive.

Long-function admission composes the existing regexp opcode and large-code
validator; short validation, frame ABI and bounds are retained. The environment
switch QJS_DISABLE_FRAME_LONG_REGEXP disables it on first classification, even
with value 0. Use a fresh process for comparison. It is targeted coverage, not
a new regexp algorithm or a broad suite-speed claim.

Component controls and fallback paths support diagnosis, embedding and compiler
upgrades. Removing them solely to reduce file/option counts would remove useful
compatibility guarantees. No JIT, PGO profile, fixed image base or external
profiler is required at runtime. Portable builds retain their declared C path;
they do not imply that Win64 native optimizations execute on another platform.

Research candidates and measurement data are not product dependencies. Further
performance work needs a reproduced application problem and a bounded plan.
Correctness, build portability, API compatibility and upstream maintenance
continue after open-ended performance exploration is closed.
