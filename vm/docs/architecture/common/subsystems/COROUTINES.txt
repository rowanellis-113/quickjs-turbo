Persistent coroutine execution on MSVC WIN_X86_64
============================================
The Windows WIN_X86_64 MSVC/MinGW native backend resumes real suspended generator, async-function
and async-generator frames through a private generated entry. Arguments,
locals, captures and PC/SP remain in their existing storage. The full inherited
C opcode loop, exception walker and suspension cleanup remain available.

The persistent resume loop is compiled in its own private C unit. The original
core compiler input stays unchanged; one verified direct async_func_resume
call relocation selects the new entry. Typed original helper imports preserve
their identity and ABI. Linker retention can still change ordinary code layout;
compiler-object identity is not a claim of identical timing or linked layout.

Contiguous supported operations run through 108 precompiled scalar handlers,
with direct successor dispatch and no runtime machine-code generation. The
native leaf uses volatile WIN_X86_64 registers, no native stack, ordinary readonly
dispatch targets with complete ASLR fixups and standard unwind metadata.
Its temporary 48-byte view borrows the real persistent slots. No public API,
JSValue, object, context, runtime or suspended-frame layout changes are made.
The 19 pinned upstream files remain unchanged.

Unsupported value types, final-owner release, overflow, negative zero, TDZ,
callbacks and interrupt boundaries return before the unsupported opcode changes
state. That original opcode runs once in the complete C loop. The generator
checks the pinned parent and retains this build's declared overlays. Source,
private ABI, COFF caller/relocation, readonly targets, unwind and regeneration
contracts remain required build checks. Derived helper extraction retains the
actual frame compiler policy, including the existing native instanceof route.

Controls and compatibility
--------------------------
GNU computed-goto, portable and MSVC Debug builds use the original entry.
Before process start, presence of QJS_DISABLE_CVM_NATIVE_SEGMENTS selects the
original path, including values 0 and 1. Existing frame/internal/register
disables do the same. QJS_DISABLE_CVM_NATIVE_SEGMENT_OPS selects the isolated
C resume loop without native scalar segments. Configuration is process cached;
compare modes in separate processes. These new flags are inactive on GNU and
portable execution. Debug builds retain the original dump/stepping behavior.

Profiles use exact installed images, matching symbols, actual PIDs, natural
bases, sampled instruction bounds and PE unwind ranges on CPU2. The bounded
extra-loop profile context is separate from original-suite timing and caller
admission. Self samples are not call counts, inclusive costs or additive
removable time. ASLR remains enabled; no PGO, padding or favorable-base choice.

The design follows precompiled handler dispatch used by the measured V8
jitless interpreter. Jitless retains native handlers, builtins and inline-cache
machinery while disabling runtime JIT. The pinned Node build has pointer
compression disabled, so compression is not assumed to explain its gap.
