Async generator output-Promise capability elision
===============================================

The original request Promise is retained. For qualified native helpers, undefined resolving
function slots mark the private capability-free state. Resolve/reject uses the original
Promise algorithm, job scheduling, hook/realm/thenable behavior and queue ownership.
Observable recovery CData functions remain real fresh functions; there is no shared
global handler or new reference-count cycle. Missing intrinsic, hook/stack/unsupported
conditions preserve conservative original behavior.

The whole private helper family, including independently emitted MSVC resolve, is copied
and checked. Only reviewed exact caller/callee shapes route to it; unknown optional
shapes emit no guessed-ABI references and retain original core bytes.

QJS_DISABLE_GENERATOR_CAPABILITY disables the worker (presence, including0). The _FAST,
QJS_DISABLE_DIRECT_AWAIT, QJS_DISABLE_SETTLED_AWAIT and capability _OUTPUT controls are
diagnostic ablations. Defaults select the qualified paths. PORTABLE retains original.

Public semantic/allocation, fresh-runtime OOM, GC/realm/hook/reentry/interrupt and
recovered callable/prototype identity checks passed; deliberate JS failures exit1.
The stable original async-fs body improves15.48% MSVC/21.61% GNU throughput. The public
n128 harness allocates2757 objects versus5587 accepted, with identical live usage and
zero teardown allocations. These counts are not application-suite dynamic counts.

Overall suites are nearly flat and retain priced micro regressions. See PRODUCT-BASELINE.txt and
external SDK REPORT.txt, DECISION-final2.json, REGRESSION-REVIEW-final2.json, original
profile and all preset image-copy records. Do not infer a universal Promise speedup.
