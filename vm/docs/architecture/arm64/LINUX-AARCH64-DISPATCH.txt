Fast opcode dispatch on Linux AArch64
====================================

This performance increment is based on product revision 10ea7a1cd78aa380c37ffee62070cb93dbdcd217.
It replaces 78 shared fast-tail branches with the original next-dispatch sequence.
The qualified ELF has 168 indirect dispatch sites instead of 2.
Per-handler indirect branch context and removal of the shared jump chain are
one joint intervention; their individual contributions were not isolated.

The same-ELF central/threaded controls have identical image bytes and code
layout. Read-only instrumented observations select 1,024,552 central fast tails
or 1,024,552 threaded fast tails, with the same 1,024,617 native VM operations,
65 activations and 26 C steps. These observer images are excluded from scores.
The production macro keeps the existing opcode counter, register clobbers,
PC/SP commits, interrupt/ownership checks and three 1024-byte relative RO tables.
Its default image adds no mode policy, C call, TLS probe or frame field.

All timing is serial on CPU 1 of the retained t4g.small/Neoverse-N1 host,
Linux AArch64, GCC 13.4, normal ASLR, allocator 256 and one build job. CPU 1 is
the recorded exception to CPU 2 because this machine only exposes CPUs 0/1.
The immutable workloads, original calibration and validation remain unchanged.

The fresh formatted build passes 1249 native and 1797 instrumented regressions.
Four full Test262 configurations each test 81,152 cases, retain the same 65
known product failures and introduce no new or changed failure identities.
Native, publication-OFF and register-OFF routes are covered against the prior
runner. All 19 pinned upstream inputs and the public API remain unchanged.
GAS/expanded OFF streams retain RX/RO/CFI/relocation byte equality. The final
qjs, qjsc, Test262 runner and library are byte-identical to the measured candidate.
The unified native/Python/CMake/shell/Meson/PowerShell/JS checks and 525 source
receipts pass in the product worktree. No compiled private fingerprint was refreshed.

Four valid UID 1000/CPU 1 captures retain 13,867 samples with no loss.
The full V8 capture covers the first 3-10 seconds of the unchanged original full
suite, not isolated case timing. A separate repeated-body float profile locates
JS_AArch64Step/js_add_slow. Original-calibration callback observations see

total C slow entries; the integer case has no corresponding arithmetic fallback.
These are path counts, not removable-time estimates or speed results. Floating
add_loc C fallback and the remaining ARM/x86 product-benefit gap stay open.
