Linux AArch64 portable C cross build & ABI foundation
=======================================================
This guide documents the common `PORTABLE` C build and standalone AAPCS64 ABI
checks on Linux AArch64 (`arm64/`). For the native register-frame assembly VM,
use `vm/tools/arm64/build/product-linux-aarch64.sh` and `LINUX-AARCH64-RELEASE.txt`.

Cross-build prerequisites on Ubuntu x86-64 (including WSL2)
-----------------------------------------------------------
  sudo apt-get install --no-install-recommends cmake ninja-build python3 \
    gcc-aarch64-linux-gnu binutils-aarch64-linux-gnu libc6-dev-arm64-cross \
    qemu-user

Portable cross build & test:
  bash vm/tools/arm64/build/product-linux-aarch64-portable.sh \
    build/linux-aarch64-portable out/sdk-linux-aarch64-portable
  QJS_EXPERIMENT_ALLOCATOR=256 qemu-aarch64 -cpu cortex-a53 \
    -L /usr/aarch64-linux-gnu out/sdk-linux-aarch64-portable/bin/qjs -e 'print(6 * 7)'

Notes
-----
- `QJS_AARCH64_BUILD_ABI_CHECKS=ON` compiles standalone AAPCS64 call-ABI test
  executables without adding assembly bridges into `PORTABLE` `libqjs.a`.
- Toolchain overrides: `QJS_TOOLCHAIN_FILE`, `QJS_AARCH64_TOOLCHAIN_PREFIX`,
  `QJS_AARCH64_TARGET_ROOT`, `QJS_AARCH64_QEMU_CPU`, `QJS_AARCH64_QEMU_LD_PREFIX`.
- `record-portable.py` writes `ARM64-BUILD.json`, `interpreter-backend.json`, and
  copies this note into `share/doc/quickjs/`.
- QEMU validates functional correctness and ELF architecture only; physical ARM
  speed and memory must be measured on native ARM hardware (`LINUX-AARCH64-HARDWARE.txt`).
- Native backend details: `LINUX-AARCH64-RELEASE.txt`, `LINUX-AARCH64-MECHANISMS.json`,
  and `workers/LINUX-AARCH64-*.txt`.
