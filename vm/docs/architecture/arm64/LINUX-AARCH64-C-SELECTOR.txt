Direct complete C fallback on Linux AArch64
==========================================

This qualified increment follows product 13357493e7d242a6c57382cfb92322cee5b44555.
The only runtime source change is tools/arm64/extended_calls.py.
Its default iterator-enabled factory avoids an ancestor-chain scan before every
C miss and selects the retained complete C executor directly. The original
for_of_next route and single opcode-observation owner remain intact. Other
compiled feature sets retain their original routing. No opcode body, public
layout, cache, experimental switch or compiled private fingerprint is changed.

The complete executor still needs the original base boundary's arities=0
invalidation of builtin-window geometry. An earlier prototype omitted it and
failed four property lifetime controls; it was rejected without weakening tests.
The qualified image retains that invalidation and passes the unchanged tests.

Same-host throughput against product 1335749:
  Original V8-v7, all 8 cases, pooled four launches per role: +5.38%
  Retained JetStream subset, all 17 original bodies:          +3.66%
  Original microbench, all 57, user CPU:                     -3.28%
  Separate elapsed microbench diagnostic, all 57:             +1.24%

Aggregates are geometric means of per-case throughput ratios. The V8 pooled
panel uses medians of all four candidate and four prior launches. Both preset
forward/reverse cohorts remain visible: +8.77% and +3.00%. Initial prior and
portable launches were slow; one later candidate launch slowed several cases.
All launches are retained. This is not a stable 8.77% claim. Pooled Earley/Boyer
falls from 78.812 to 58.954 ms, about 25.2% less time / 33.7% more throughput.

Original user-CPU minima have large modes even for an immutable image. The
elapsed diagnostic changes only os.cputime to os.now, preserving bodies and
calibration. It remains a separately labeled diagnostic. Original CPU losses
are retained, including focused slice3 and float_toString results.

Original-calibration elapsed rechecks confirm throughput costs of 8.44% for
weak_map_set, 4.67% for func_call and 2.85% for string_slice3. Their added time
relative to stock is respectively 4.89%, 4.69% and 3.63%. Full-panel slice1
throughput was -9.75%, but its focused result was -1.26%; both remain recorded.
JetStream delta-blue is -3.79% and Babylon -2.57%. TypeScript is +16.23% and
Acorn +18.25%. These costs are accepted for the broad suite improvement.

All measurements use the retained t4g.small/Neoverse-N1 ARM machine, GCC13.4,
normal ASLR, allocator256, CPU1 and one build job. CPU1 is the documented
exception because this host only exposes CPUs0/1. Workload bytes, feature flags,
original calibration and validations match the prior, portable and stock roles.
V8 maximum peak RSS is 183812/183048 KiB candidate/prior; JetStream is
151236/151340 KiB. No material peak-memory increase is observed in these panels.

Post-change repeated-body perf captures retain 3453 candidate and 3450 prior
samples, UID1000/CPU1, no lost events, READY/GO with a three-second delay and a
seven-second 499Hz DWARF window. The old selector has 958 prior self samples
and no candidate self samples. These extra loops are excluded from scores;
sample fractions are not additive removable-time estimates. The selector
function shrinks from188 to44 bytes. VM allocated sections and normalized
relocations are identical, but C code generation and linked placement change.
Executable section bytes rise from1415904 to1426784. The whole benefit cannot
be attributed exclusively to the eliminated scan.
