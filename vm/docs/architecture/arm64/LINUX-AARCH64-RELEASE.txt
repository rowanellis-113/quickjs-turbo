Linux/glibc & musl AArch64 implementation and release boundaries
================================================================
Current release: `v0.17.0-turbo.2` (Waves 1–6c verified baseline, 2026-11-25).
Pinned upstream: QuickJS-NG `0.17.0` (`7b5f588e0f9b643e2996f291bfc861abeaceddc2`;
all 19 upstream source pins exact).

Build & Architecture
--------------------
- Owned code lives under `vm/asm/arm64/`, `vm/src/arm64/`, and `vm/tools/arm64/`.
- Wrapper (native ARM64 or x86 cross + QEMU):
    bash vm/tools/arm64/build/product-linux-aarch64.sh build/arm64 out/sdk-arm64
- CMake `AUTO` automatically selects `LINUX_AARCH64` on supported Linux AArch64 (`glibc`
  & `musl`) hosts with GCC 13/14+ and falls back to `PORTABLE` under sanitizers, fuzzers,
  shared libraries, or BTI/PAC-default toolchains. `JS_FrameInterp` is strictly 64-byte aligned
  via `check_vm.py` (`161` native opcodes including `OP_push_bigint_i32`, full FDE, PIE, NX, `no-WX`).
- Public `quickjs.h` ABI, installed `quickjs-turbo::qjs` CMake consumers, and
  `QJS_USE_PREGEN_ASM=ON` Python-free builds (`linux_aarch64`: 137 pregen files)
  are fully supported. See `../common/ABI-AND-BASELINE-JIT.txt` for the pinned
  register-frame ABI contract (`x19..x27`) and optional Baseline JIT design.
