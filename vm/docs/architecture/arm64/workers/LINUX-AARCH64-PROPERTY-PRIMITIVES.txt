Linux AArch64 live methods and logical length
============================================

The accepted semantic owners are tools/x86/common/codegen/length.py,number-property.py,
proto-load.py and their complete common C bodies. Their hashes,actual compiler
types and the native ARM implementation are bound by the primitive-property
contract. No Win64 registers,offsets,aggregate ABI or object code is imported.

OP_get_length reads the original string code-unit length or a fast Array's
logical length property. It never substitutes dense element count. Integer
and floating Array lengths are retained exactly. A native hit requires a
nonlast receiver reference and consumes it once. Last release,unsupported
representations/classes and disabled policies retain the original C owner.

OP_get_field2 may read a live plain data property on the calling bytecode
realm's String/Number prototype. String length and integer atoms keep their
original route. Number retains the accepted original holder-class guard and
complete atomic/environment policy initialization. Its once-only cold call is
standard AAPCS64 void(void),with no JS/runtime/GC/allocation access;the native
handler then reloads every volatile input. A read-only natural debugger stop
verifies this call's VM backtrace and aligned physical stack.

Ordinary and Array method receivers may also use the accepted live own/hash
lookup and bounded32-edge prototype walk. Exotic prototype absence,accessors,
missing or unusual descriptors retain original observing C. Results are
duplicated before push and the method receiver remains owned by its caller.
There are no cached holder pointers,new strong roots,allocations,last releases
or observing calls on these native hits. A normal active four-way PIC site
still enters its original learner first;the supplement does not bypass it.
