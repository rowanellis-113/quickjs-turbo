Architecture & Advantages

Why QuickJS-Turbo?

Built for production hosts that want QuickJS's tiny footprint, instant cold start, and strict security invariants — without leaving 1.5×–7.0× execution speed on the table.

01 · ZERO JIT / W^X / CET

Fast Where JITs Are Banned

Ahead-of-time assembly VMs require zero executable heap pages. Ships with complete DWARF CFI / Win64 SEH unwind tables and 139/139 Linux CVM CET-IBT endbr64 jump targets for iOS, consoles, locked-down containers, and edge workers.

PIE · NX stack · 0 RWX · 139/139 CET-IBT endbr64
02 · NATIVE VM + CVM + TIER-5

Register VM, Zero-Spill CVM & Constructors

Combines register-pinned assembly dispatch, zero-spill native CVM coroutine executors across x86-64/Win64/ARM64, Tier-5 straight-line VA constructor compilers, fused compare-branch loops, and native PE TLS on Win64 MinGW.

RayTrace +53% Linux / +16% ARM64 · V8-v7 99.2% x86 / 95.5% ARM64 vs V8
03 · REGEXP, BIGINT & RUNTIME

Zero-JIT RegExp, 256-bit BigInt & JSON

Adds zero-JIT RegExp range/sticky/greedy scanning, 256-bit/Curve25519 BigInt kernels, fast dtoa/atod, DataView, array splice copy-grow, and zero-alloc ready await across Linux x86-64, Win64, and ARM64.

RegExp 5.67×–5.93× · json-stringify 6.97× · bigint-ed25519 beats V8

Deterministic RC, Bounded Peak RSS

Keeps QuickJS's immediate reference counting while generational partial cycle GC and large-heap tuning cut full-heap scans by 85.8% and hold ARM64 TypeScript RSS -24.1% lower than turbo.3 while beating Bellard on Linux & Win64 TypeScript.

ABI Contract & Execution Roadmap

Verified Register-Frame ABI & Optional Baseline JIT

QuickJS-Turbo separates its immutable public C ABI from an internal register-frame execution ABI — delivering strict zero-RWX safety today while providing ~70% of the runtime substrate for an opt-in, zero-AST Baseline JIT directly over QuickJS bytecode.

Two-Layer ABI Contract

Shipping today across Linux x86-64, ARM64, macOS, and Windows

Production Invariant
  • 100% Drop-In Public C ABI: Unmodified quickjs.h, 16 B JSValue representation, and BC_VERSION 29 wire format verified on txiki.js v26.11.0; all tuning in quickjs-turbo.h is strictly additive.
  • Pinned Register-Frame & CVM ABI: Callee-saved hardware pinning (x19 state, x20 PC, x21 SP, x22 frame, x23 locals, x24 args on AArch64; equivalent x86-64 SysV/Mach-O/Win64 contract) over the contiguous JSFrame arena plus zero-spill CVM coroutine segments.
  • Clean/Dirty Lazy Publication: Fast paths skip cur_pc/cur_sp writes until call, GC, exception, or finalizer safepoints, pre-validated by FRAME_KIND and a jump-target boundaries bitmap.
  • Fail-Closed Build Contracts: core-fields.json + 511 SHA-256 ABI receipts, full DWARF CFI FDEs, Linux CET-IBT endbr64 jump targets, and Win64 SEH .pdata/.xdata unwind tables.

Proposed Bytecode-Driven Baseline JIT

Future Opt-In Tier (Not Shipped in v0.17.0-turbo.4) · Zero AST · Strict W^X

Proposed · Not Shipped

Even with native dispatch, zero-spill CVM, and inline caches, an interpreter still pays per-opcode dispatch, operand decode, and [sp] stack traffic. A proposed opt-in Baseline JIT (design roadmap only — not shipped in v0.17.0-turbo.4) would eliminate that tax directly on the existing ABI while keeping the 0 RWX ASM VM as default:

01
Direct Bytecode (No AST): Compiles JSFunctionBytecode linearly — preserving the 96.29 KiB cold heap, sub-ms parse, and 1:1 pc mapping for OSR/exceptions.
02
1-Pass Virtual Stack + Copy-and-Patch Stencils: Offline-verified stencils + 2–4 reg basic-block TOS cache fold get_loc + add + if_false without [sp] ping-pong or indirect dispatch.
03
Zero-Bridge ABI & Direct-Baked ICs: Shares JSFrame, Clean/Dirty bailouts, and Hybrid GC; bakes Property IC slot pointers PC/RIP-relatively and adds Loop OSR.
04
Strict W^X & Hotness Gate: Hotness threshold (64–128) keeps cold scripts at 0 B JIT memory; bounded Code Arena transitions RW → RX (never simultaneous RWX).
Proposed gates: Phase 0 PoC (≥1.35× loops) → Phase 1 IC/Call → Phase 2 x86/ARM64 + Test262 ABI-AND-BASELINE-JIT.txt ↗
